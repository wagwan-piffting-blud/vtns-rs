# Unit database and unit selection: vt_eng.dll 3.11.7.1 (Paul M16)

This document covers the unit database and unit selection:
- the unit database as unit selection sees it (`dblist.idx`, `unit-*.idx` columns, class tables, `cepdist.tbl`, the scalar distance table, `.his` files);
- the full selection algorithm: target building, the context back-off lattice, candidate generation, contiguity scoring, target cost, join cost, Viterbi, beam pruning and backtrack;
- the `.dtt` info dump.

The Rust port is `src/unitsel.rs`, `src/classes.rs` and `src/unitsel_tables.rs` (generated by a DLL-table extraction script, not part of this repository). It is **bit-exact** against the engine: see [Parity](#parity).

| **[E]** | Verified on the Paul data files or the harness captures |

## Pipeline at a glance

Per phrase, `FUN_1002c9b0` calls `us_SelectUnitsForPhrase(phrase, TIB, voiceDB)` (`0x10024980`):

```
final_type = (phrase == last phrase of sentence) ? SS.sentence_type : 5     -> TIB+0x1312de
N = us_BuildTargets(phrase)                  one target per phone with dur > 0, or two half-phone targets
if N == 0: return
us_GetCandidates(0)                          expand classes -> units, contiguity, target cost, keep <= 30
acc[0][j] = f32(cand[j].tc / 2.0)
for t in 1..N:                               us_ViterbiForward(1, N-1)
    us_GetCandidates(t)
    us_ViterbiJoinStep(t)                    acc[t][j] = min_k(join + acc[t-1][k]) + tc/2
    us_BeamPrune(t, 1)
us_Backtrack(0, N-1)                         path from argmin of acc[N-1]
for t: us_ReadPrimaryRecord(kept[t][path[t]]) -> TIB+0x46c93*4 + 0x18t   (0x18-byte DB entries)
if .his mode: count candidates (post-prune) and chosen units
```

The waveform stage (`wav_BuildUnitRecords`, 0x1002c220) then turns the 0x18-byte DB entries into 0x34-byte unit records.

## Data structures

### Target record (`TIB+0xec628 + 6t`, one per target of the phrase) **[D][P]**

| Off | Field | Notes |
| --- | --- | --- |
| +0 | word | Absolute word index in the sentence structure |
| +1 | syllable | Index into the word's syllable array: the phone's syllable, found by accumulating `syl.n_phones` (`+0x1d`) |
| +2 | phone | Index within the word |
| +3 | idx | Target number within the word (`word+0x92` before the increment; +1 for a right half). The harness calls this `syl_phone` |
| +4 | half | 0 whole, 1 left half, 2 right half |
| +5 | unvoiced | `ba44[ctx[2]] == 0` |

### Per-target slot (`TIB+0xae894 + 0xfc t`) **[D]**

| Off | Type | Field |
| --- | --- | --- |
| +0x00 | s16 | total classes in the list |
| +0x02 | s16 | size of the preferred B-list (the first entries of the list) |
| +0x04 | s32[] | class list: B first, then A\B in ranked order (≤ 60 entries; entries ≥ 30 overlap the kept list below, harmlessly) |
| +0x7c | s32[30] | kept unit ids (beam) |
| +0xf4 | s16 | n: first the expanded count, then the kept count (≤ 30), then the post-prune count |

Beam arrays: `acc` f32 at `TIB+0x8212c + 0x78t`, backpointers s16 at `TIB+0x9f664 + 0x3ct`, join scratch f32[30] at `TIB+0x9f5ec`, path s16 at `TIB+0xae0c4 + 2t`.

### Candidate pool **[D][P]**

`TIB+0x477ac` is an array of 10,000 pointers, initialized to 10,000 consecutive 0x14-byte records at `TIB+0x513ec` when the TIB is created (`FUN_10025fc0`, once per request). The records come from `malloc` (a large block, zero pages). Every access goes through the pointer array and the sorts permute that array, so fields the current call does not rewrite keep **stale values from earlier targets or phrases**. The port models the pool plus the permutation exactly; the harness's `pref` field depends on it.

| Off | Type | Field |
| --- | --- | --- |
| +0x00 | f32 | `tc`: target cost |
| +0x04 | f32 | `score`: sort key (contiguity score, class distance, or domain-weighted TC) |
| +0x08 | s32 | unit id (a class id while ranking classes) |
| +0x0c | s16 | `fwd_run` |
| +0x0e | s16 | `run` |
| +0x10 | s16 | `wrun`: weighted run |
| +0x12 | u8 | `pref`: the unit's class is in the B-list |

## Unit database files

The byte layout of `unit-*.idx` / `.dat` / `.upm` is specified in `README_TECHNICAL.md` (this layout, and the unit index in general, was also independently verified by an outside review — see `EXPERIMENTS.md`). What unit selection relies on:

- **Pools.** `dblist.idx` lists the pools, which are merged into one global unit array in dblist order: gen `[0, 440124)`, num `[440124, 464632)`, etc `[464632, 580355)`, alp `[580355, 580474)` **[E]**. Tag → domain: GEN 0, DOMAIN 1, ABC 2, NUM 3, SYL 7, NUM_SPLIT 8, EXP 0x0c, anything else 100 (`'d'`). Paul's etc and alp are tagged `ETC` → 100 **[D]**.
- **EXP flag.** At load, every unit from a domain-0x0c file gets label flag `|= 0x20` (end of `us_LoadUnitIndexes`, 0x10019f40) **[D]**. Paul has none.
- **Primary record.** The 19-byte record is read lazily for chosen units only (`us_ReadPrimaryRecord2013`, 0x1001b0d0). The resulting DB entry: `+0 pcm_pos`, `+4 pm_pos`, `+8..0xa` first/shared/last period (half-samples), `+0xc h1`, `+0xe h2`, `+0x10 coded`, `+0x12 pm1`, `+0x13 pm2`, `+0x14 file` **[D][E]**. Matches all 3,269 runtime reads.
- **`cepdist.tbl`.** `u16 n = 1024`, then `f32` lower triangle, row i = `d(i, 0..i)`. Lookup `d[max][min]` on `spec & 0x3fff` **[D][E]**.
- **Scalar distance** (`us_ScalarDist` 0x1001ae20), built for 0 ≤ b ≤ a ≤ 255: `m = f32((a+b)/2.0)`; `m == 0 ? 0 : f32(f32(a−b)² / m)` **[D][P]**.

## Class index

Rebuilt at load because `class.idx` / `classhp.idx` are not installed **[D][P]**:

1. `key5(u) = us_LabelToClassKey(label[u]) = {mapL[L1] (b7ec), C (b788 = identity), mapR[R1] (b850), posbits, flags & 0x20}`.
2. Classes are the distinct keys in ascending unsigned byte order. Each class lists its units in ascending id order (`us_IntroSortInts` over each class's run), so the result does not depend on sort stability.
3. **Half-phone orderings.** For mode m = 1 (left) and 2 (right), the 10-byte half keys of all classes are sorted with Numerical Recipes `sort2` heapsort (`us_NRHeapSortHalfKeys` 0x1002dd70) on unsigned 10-byte compare, carrying class indices. Classes with **equal** half keys stay in heapsort order, and that order is what later feeds class ranking, where ties matter.

Half key (`us_HalfPhoneKey`, input key5 `k`; `b = k[3]`; `lpos = b>>3 & 7`, `rpos = b & 7`; `lb = (b&0x80) && lpos ≥ 2`; `rb = (b>>6&1) && rpos ≥ 2`):

| byte | mode 1 (left half) | mode 2 (right half) |
| --- | --- | --- |
| 0 | 0 | 1 |
| 1 | k[4] (EXP bit) | k[4] |
| 2 | k[1] (centre) | k[1] |
| 3 | b97c[k[0]] (broad class of L) | b97c[k[2]] |
| 4 | lb | rb |
| 5 | b8b4[k[0]] | b918[k[2]] |
| 6 | lpos·10 + rb | rpos·10 + lb |
| 7 | k[0] | k[2] |
| 8 | rpos | lpos |
| 9 | b97c[k[2]] | b97c[k[0]] |

## Target building

`us_BuildTargets` (0x10024680) **[D][P]**, for each word of the phrase:
1. Set `word.ntargets = 0` and `word.first_target = n`.
2. For each phone k:
   - Fill the target record (word, syllable of k, k, unvoiced).
   - If `dur[k] > 0`:
     - `r = LookupWholePhone(n)`; if `r < 1`, `r = LookupHalfPhones(n)`.
     - `word.ntargets += r`, `n += r`.

Phones with a non-positive predicted duration get **no target**.

**`us_LookupWholePhone`** (0x10024060):
1. Set `idx = word.ntargets`, `half = 0`, and clear lists A and B.
2. If `word.domain == 0x0c`:
   - Run the lattice on a copy of the label with `flags &= 0xdf`, mode 1. If A is empty, return 0.
   - Then run the lattice on the real label, mode 2.
3. Otherwise run the lattice on the label, mode 1.
4. A ← `sort_unique(A)`, then `LimitClasses(30, 10000, A, label)`. B ← `sort_unique(B)`.
5. Class list = B ++ (A \ B), in A's order. Return `1` if `units(list) > 9` (or `> 0` when `domain == 8`), else `0`.

**`us_LookupHalfPhones`** (0x100242a0), for h = 0, 1:
1. For h = 1, target t+1 = a copy of t.
2. Set `half = h+1` and `idx = word.ntargets + h`.
3. Run the lattice on the label (mode 1). For a domain 0x0c word, run it first on a copy with `flags &= 0x80` in mode 1, then on the real label in mode 2.
4. A ← `sort_unique`, then `LimitHalfClasses(30, 10000, A, label, half)`. B ← `sort_unique`.
5. Class list = B ++ (A \ B).

Always returns 2.

## Context back-off lattice

`us_ContextBackoffLattice(L, t, mode)` (0x10018770). Mode 1 is the primary pass, which may seed the B-list; mode 2 is always kept; mode 0 is used for recursion and substitutions **[D][P]**:

```
saved = |A|
b = L[5]; lb = b>>7; rb = b>>6&1; lpos = b>>3&7; rpos = b&7
left  = LEFT_POS_LISTS [lb*5 + lpos]        (c4dc)
right = RIGHT_POS_LISTS[rpos + rb*8]        (c504)
code  = word.edge_code[phone]; tens = code/10; ones = code%10
found = false
for i, v in left:
    f3 = (v == 0) ? 0 : lb;   aok = v in {0, 1}
    l6 = (aok == (lpos <= 1))
    if !(tens == 0 || l6 || target.half == 2): continue
    for j, w in right:
        f5 = (w == 0) ? 0 : rb;   bok = w in {0, 1}
        l7 = (bok == (rpos <= 1))
        if !(ones == 0 || l7 || target.half == 1): continue
        key = L
        if i == 0 && j == 0:
            r = lookup(key, mode)
            if mode == 1 && saved == 0 && r > 0: B = A[0 .. min(|A|, 30)]
        else:
            if i > 0 && lb && v > 2: key[0] = key[1] = c4a4[v]
            if j > 0 && rb && w > 2: key[3] = key[4] = c4a4[w]
            key[5] = ((f3*2 + f5)*8 + v)*8 + w        (u8 arithmetic)
            r = lookup(key, 0)
        if r != 0 || lb || rb:
            if c2c4[L[2]] == 0:
                c1 = c2c4[L[1]]; c3 = c2c4[L[3]]
                if c1 == 0:      if c3: key[3] = c3; r += lookup(key, 0)
                elif c3 == 0:    key[1] = c1; r += lookup(key, 0)
                else:            key[1] = c1; r1 = lookup(key); key[3] = c3; r2 = lookup(key)
                                 key = L; key[3] = c3; r3 = lookup(key); r += r1+r2+r3
            elif (rb || L[2] != 0x39 || (i8)bb70[L[3]] < 1) && word.mflag[phone] == 0:
                key[2] = c2c4[L[2]]; r += lookup(key, 0)
            if !found && r > 0 && l6 && l7: found = true
if mode != 2 && !found: |A| = saved; return false        (B is left as is)
if mode != 0 && c324[L[2]]: key = L; key[2] = c324[L[2]]; lattice(key, 0)
return true
```

`lookup(key, mode)` = `us_LookupClasses`:
- **Whole target** (`half == 0`): `us_LookupWholeClassExact` does a 5-byte exact class-key range search and appends the range. List A is capped at 300 classes.
- **Half target**: `us_LookupHalfClassBackoff`:
  1. If `|A| > 289`, return 0.
  2. Search the half ordering with prefix length 10, shortening by 1 until something matches. In a non-primary mode, give up once the prefix is below 6.
  3. Rank and limit the range to ≤ 10 classes / 10000 units (`LimitHalfClasses`).
  4. While the result has ≤ 9 units and the prefix is ≥ 1, shorten the prefix (again giving up below 6 when `mode != 1`) and redo steps 2–3.
  5. Append the result.

## Class ranking and limiting

`us_LimitClasses30x10000` / `us_LimitHalfClasses` **[D][P]**:
1. If `|src| ≤ maxc` and `units(src) ≤ maxu`, keep `src` as is.
2. Otherwise:
   - Load pool records 0..|src|−1 with `{id = class, score = (f32)dist(key5(label), key5(class), half)}`.
   - `us_SortByScore`.
   - Take classes in order, at most `maxc`. Stop after the first class that pushes the unit total above `maxu`; that class is kept.

`dist` = Σ `bf14[i]` over mismatching class-key bytes (weights 40, 1, 40, 10, 1000), plus, for half targets, Σ `bf28[i]` over mismatching half-key bytes (50000, 20000, 10000, 5000, 1000, 2000, 500, 100, 50, 20).

## Candidate generation

`us_GetCandidates(t)` (0x10023350) **[D][P]**:

1. **Feature** `{dur_code, f0_a, f0_b}`:
   - `dur_code = clamp(trunc(f32(dur)/50.0 + 0.5), 0, 255)`, where `dur` is the phone's predicted duration, halved (C `/2`) for half targets (`pro_QuantizeDurationDiv50` 0x10022fd0).
   - Over the word's targets on the same syllable, sum only *voiced* targets' durations (halved for halves): `before` (targets with idx < t.idx), `upto = before + d(t)`, and `total`.
   - Then `a = min(before·12/total, 11)` and `b = max(upto·12/total − 1, a)`; both are 0 if total = 0.
   - `f0_a = (u8) syl.f0[a]` and `f0_b = (u8) syl.f0[b]`: the low byte of the Hz value.
2. **Expansion.** Every unit of every class in the list, in list order and ascending id order inside a class, up to 10,000 units (`n`).
3. `us_ScoreContiguity(t)` sorts the n candidates by `−(run + 100·wrun)`.
4. **Cutoff `count`:**
   - If `cand[0].run == N` (a run covering the whole phrase): count = the leading candidates with `run ≥ N`.
   - Otherwise:
     - A word domain of 0x0c is reset to 0 (**mutation**).
     - If `n < 31`, count = n. Otherwise count extends to the end of the tie group straddling position 30: scanning i = 1..n−1, whenever `score[i−1] < score[i]`, record `sort_from = i` while `i < 30`; at the first such i ≥ 30, stop with count = i.
5. **Preferred fill** (only if count > 30):
   - Mark `pref` for the first `count` candidates whose class is in the B-list, and count them (`n_pref`).
   - If `n_pref < 10` and the B-list has ≥ 10 units: scan idx = count..n−1, stopping once `n_pref ≥ 10` and `score[idx] ≠` the score of the 10th preferred found. Copy each B-list candidate's `{id, run, fwd_run, wrun}` into record `count` (`pref = 1`) and increment count and `n_pref`.
   - The copy does **not** move `tc` or `score`.
6. **Target cost** for i < count:
   - `r = f32(f32(run)/2.0)`, raised to 1.0 if `r ≤ 1.0`.
   - `w = f32(1.0 / (wrun + r))`.
   - `tc = us_TargetCost(uid, t, feat, w)`.
7. **Keep:**
   - If count ≤ 30: keep = count.
   - Otherwise, for i in [sort_from, count), set `score = tc × 5` (domain 100), `tc × 10` (EXP unit, non-EXP word), or `tc`. Sort that range and keep 30.
8. **Kept list:** `kept[i] = cand[i].id`.
9. **Preferred substitution** (only if count > kept):
   - Let p = the number of preferred among kept. If `p < 5` and `p < n_pref`, then e = kept − 1.
   - For each preferred candidate beyond the kept ones: step e down past kept entries that are already preferred (`while e > 0 && cand[e].pref == 1`), set `kept[e] = uid`, then p++ and e−−. Stop when `e < 1` or `p ≥ 5`.
   - The `tc` used later for slot e is still `cand[e].tc`, **not** the substituted unit's. This engine quirk is reproduced.

## Contiguity scoring

`us_ScoreContiguity(t)` (0x100230a0). Label flag 0x80 on unit u means "unit u+1 continues the recording" **[D][E][P]**. Weights by half: `{2, 1, 1}`.

- **Backward**, from k = t−1 down to 0: unless target k is a left half (same unit), move to u−1. Stop if u−1 < 0 or `label[u−1].flags & 0x80 == 0`. Stop if the unit is not in target k's kept (post-prune) beam. Otherwise `back++` and `wback += w[half_k]`.
- **Forward**, from k = t+1 up: unless target k is a right half, require `label[u].flags & 0x80` and move to u+1. Stop if `class_of[u]` is not in target k's class list. Otherwise `fwd++` and `wfwd += w[half_k]`.
- **Results:**
  - `run = fwd + 1 + back`, `fwd_run = fwd`.
  - With `wb = (i16)wback/2` and `wf = (i16)wfwd/2`: `wrun` = `wf+1+wb` if `run == N`; else `wf` if `back == t`; else `min(wb, wf)` if `fwd ≠ N−t−1`; else `wb`.
  - `score = −(f32)(run + 100·wrun)`, then `us_SortByScore`.

## Target cost

`us_TargetCost(uid, t, feat, w)` (0x100182e0). T is the target label, U the unit label, both `{L2, L1, C, R1, R2, pos, flags}` **[D][P]**. The penalty is an integer:

| Term | Rule |
| --- | --- |
| Centre | `U.C ≠ T.C`: 100 if either is 0x4B (TQ), else 1000 if `b6c0` differs, else 5 |
| Left context (not right halves) | `U.L1 ≠ T.L1`: 1 if U's left edge is flagged (`pos&0x80` and `pos&0x38 ≥ 0x18`), else 5 same `b6c0`, else 10 same `b97c`, else 500 |
| Right context (not left halves) | `U.R1 ≠ T.R1`: 100 if final_type = 5 and T.R1 = pad, else 1 if U's right edge is flagged (`pos&0x40` and `pos&7 ≥ 3`), else 100 if U.R1 = TQ, else 5 same `b6c0` (0 if T.R1 = 0x5B), else 10 same `b97c`, else 500 |
| Position | `c0d8[T.lpos·5 + U.lpos] + c13c[U.rpos + T.rpos·8]` |
| Stress, equal centre stress | If T.L1 is a vowel and T.C ∈ {R (0x36), L (0x2B)}: `c23c[st(T.L1)·3 + st(U.L1)]`, +100 if T.L1 ≠ U.L1. Else, if U.rpos = 0 and T.R1 is a vowel: `c260[st(T.R1)·3 + st(U.R1)]` |
| Stress, unequal centre stress | `c23c[st(T.C)·3 + st(U.C)]` |
| Domain | +10 if the unit's file domain is 100; +1000 if EXP unit and non-EXP word |

The continuous term, using `sd(a, b)` = the scalar distance table and `dd = sd(feat.dur, U.dur_code)`:
- **Voiced target**:
  - Boundaries `(ka, kb)` = (0,1) for a left half, (1,2) for a right half, (0,2) otherwise.
  - `s = f32(sd(f0_b, fF[kb]) + sd(f0_a, fF[ka]))`.
  - If U.lpos ≤ 1 and U.rpos ≤ 1: `s = f32(s/2)`. Otherwise `s = f32(s/8)` and `dd = f32(dd/8)`.
  - `cont = f32(s + dd)`.
- **Unvoiced target**: `pen /= 2` (C truncation) if U.R1 = T.R1; `cont = f32(dd/5)`.
- EXP unit on an EXP word: `cont = f32(cont/16)`.

Result: `f32((f64)cont·w + (f32)pen)`, stored by the caller.

## Join cost and Viterbi step

`us_ViterbiJoinStep(t)` (0x10018c80) **[D][P]**.

**Join type** from the unvoiced flags (cur, prev):

| cur / prev | Type |
| --- | --- |
| voiced / voiced | 0 (same word), 4 (different words) |
| voiced / unvoiced | 1 |
| unvoiced / voiced | 2 |
| unvoiced / unvoiced | 3 |

**Boundaries compared**: prev end (k = 2, or 1 if the current target is a right half) against current start (k = 0, or 1 for a right half).

For each kept unit j of t, with `tcj = f32(cand[j].tc / 2)`, and each kept unit p of t−1:
- **Zero join** if (u = p and cur is a right half) or (p = u−1 and `label[p].flags & 0x80`).
- **Otherwise**:
  - `join = f32(sd(fF_p, fF_u)·wF + sd(fB_p, fB_u)·wB + cep[p][u]·wC + 2.0)`, with weights `c288[type]`.
  - Penalty for a right-half target: 5 (0 if the same unit), +1000 if the centres differ.
  - Penalty for any other target:
    - Edge flags: prev right-edge ≠ cur left-edge → 1000; both set → `bfd8[cur.lpos + prev.rpos·8]`; otherwise 0.
    - `prev.C ≠ cur.L1`: +1000 if `c384` marks either code, else +100 if `c2c4[prev.C]`.
    - `prev.R1 ≠ cur.C`: +1000 if `c384` marks either code, else +100 if `c2c4[cur.C]`.
    - +10 if cur left-edge = 0, the targets are a vowel→`c3e4` or `c444`→vowel pair, and p ≠ u−1.
  - Always add `c544[class_p·3 + class_u]`, plus 2000 if exactly one of the two units is EXP.
  - Divisor: 1 if cur is a right half or the edges are not both set; `(lpos == 2) + 1` if lpos < 3; 8 otherwise. It keeps its previous value across zero joins, which is harmless.
- `scratch[p] = f32(join/f32(div) + f32(pen) + acc[t−1][p] + tcj)`.

Finally `back[t][j] = argmin(scratch)` (first minimum) and `acc[t][j] = scratch[back]`.

## Beam pruning and backtrack

**`us_BeamPrune(t, 1)`** (0x10024510) **[D][P]**, applied only if `word.domain == 0` and n > 10:
1. Sum `acc` with an f32 store after each add, and take the strict minimum.
2. `mean = f32(sum / f32(n))`, `spread = f32((mean − min)/4)`, `thr = f32(1.0·spread + mean)`.
3. Keep j if `acc[j] ≤ thr` or `cand[j].fwd_run ≠ 0`. `cand[j]` is pool slot j, not necessarily the kept unit after a substitution.
4. Compact acc, back and kept in place.

The first target is never pruned. EXP words are never pruned.

**`us_Backtrack`**: `path[N−1] = argmin(acc[N−1])`, then `path[t−1] = back[t][path[t]]`.

## Sorting routines (tie order)

Integer-valued scores tie constantly, so the tie order must match the engine's.

**`us_SortByScore`** (0x1001b5f0) is an introsort **[D][P]**:
- **Small ranges** (`hi − lo ≤ 16`): stable insertion sort with strict `>`.
- **Larger ranges:**
  1. Median-of-three on lo/mid/hi, swapping when `>`, with pivot = `a[mid]`.
  2. Partition: `do i++ while a[i] < pivot`, `do j−− while a[j] > pivot`, swap while `j > i`.
  3. Recurse on the smaller side through an explicit stack (lo/hi arrays of 32).
  4. If one side exceeds 32× the other, heap-sort the larger side with `us_HeapSortByScore`: a bottom-up heap that descends to a leaf and then climbs back, as in the port.
- All comparisons are `FCOMP` on f32, with "not greater" for `≤`.

**`us_NRHeapSortHalfKeys`** is exactly Numerical Recipes `sort2`.

The integer sorts' results do not depend on stability.

## Floating point

- **Precision.** The code is VC6 x87 at the default 53-bit precision control. Every intermediate is therefore an IEEE double operation, and results round to f32 exactly where the compiler stores to a `float` (`FSTP dword`).
- **How the port matches it.** The port computes in f64 and rounds with `as f32` at those points (listed in each formula above).
- **The 64-bit voice DLLs** (`vt_pau/vt_kat/vt_jul/vt_jam.dll`, MSVC x64 SSE) evaluate `float` expressions in single precision. Only two places change results: the target-cost tail `FUN_18001bc30` = `f32(f32(cont·w) + pen)`, and the join step `FUN_18001c7a0`: `join = ((df·wf + cep·wc) + db·wb) + 2`, `scratch = (join/div + (tcj + acc)) + pen`, all f32 and in that order. The other f32 sites give identical results (single operations on exact inputs). The port does both behind `Selector::x64`.
- **Conversions.** `__ftol` truncates toward zero.

## Domains, EXP words and `vtml_emotion`

- **Where the domain comes from.** Word domain `word+0x2df` is set by VTML tag-span list 7. **`<vtml_emotion …>` marks every word inside it with 0x0c** **[E]** (captures `dom_emotion*`). None of the other VTML tags tried (`vtml_partofsp`, `vtml_sayas` digits/characters, `vtml_sub`, spaced digits) produced a non-zero domain **[E]**. Domain 8 was not observed.
- **What an EXP word changes:**
  - The whole-phone lookup runs a first lattice pass without the EXP bit, then a mode-2 pass.
  - Half-phone lookups keep only the contiguity bit.
  - Pruning is disabled.
  - GetCandidates resets the word to domain 0 as soon as one of its targets lacks a full-phrase run, and later targets of the word then see domain 0.
  - With Paul having no EXP units, the 1000/2000/×10 EXP penalties never fire, but the lookup and prune differences do.

## Unit-select history (`.his`)

- **Enabling.** `VT_SetUnitSelectHistoryMode_ENG(1)` sets `DAT_100a045d` before the first load.
- **Load.** `us_LoadSelectHistory` (0x100125d0) reads `sprintf("%s%s.his", speaker+0x694 = "<root>data-paul/M16/mc_idx_tbl/", poolName)`. The pool name is the dblist file name with `.idx` stripped (0x10019f40, compare against `".idx"` at 0x1007c5b0), giving e.g. `unit-gen.his`.
- **Format.** `u32 N`, then `N × {u32 times_candidate, u32 times_chosen}`. A missing file gives zeros; a count mismatch fails.
- **Counting.** After every phrase, each unit in every target's post-prune beam gets +1 candidate, and each chosen unit gets +1 chosen.
- **Save.** `us_SaveSelectHistory` writes the same layout on unload.
- **Effect.** None on selection. The port has `load_history` / `save_history` / `Selector::history`.

## VTDTTS info dump (`.dtt`)

`VTDTTS_MakeInfo_ENG` → `us_VTDTTS_MakeInfo_Impl` (0x10022350) opens `<name>.bin.dtt` (binary) and `<name>.asc.dtt` (mode `"wt"`) at TIB+0x122854 / +0x122858.

**Header** (binary):

| Field | Size |
| --- | --- |
| `"VTDTTS BINARY\0"` | 14 bytes |
| version | u8 = 3 |
| number of .dat files | u8 |
| each `.dat` file name | NUL-terminated |

The ASCII file mirrors it as `%s\n` / `%d\n` lines followed by a blank line.

The engine then sets TIB+0x122851 = 1 and synthesizes normally. `wav_BuildUnitRecords` calls `us_DumpDttRecords` (0x1002ca10) for every unit record (0x34 bytes at TIB+0xeddf8) with length ≠ 0. Binary field sizes, with the ASCII label in brackets:

**Every record:**
- `type` u8 [`TypeFlag : %d`]

**Silence** (type 1):
- `len` u32 [`Size : %d`], then a blank line.

**Unit** (type 2):
- phone name from the 5-byte table at 0x1007bc98, indexed by record +0x32 (the centre code), NUL-terminated [`PhoneString : %s`]
- `file` u8 [`File Index : %d`]
- `pcm_pos` u32 [`PCM Pos : %d`]
- `len` u16 [`PCM Size : %d`]
- `coded` u16 [`PCM Coded Size : %d`]
- `mode` u8 [`Phone Mode : %d`]
- **mode 2 only:** `h1 − ovl_l` u16 [`Shift Size : %d`]
- `ovl_l` u16 [`Pitch_first : %d`]
- `ovl_r` u16 [`Pitch_last : %d`]
- `pm_pos` u32 [`PM Pos : %d`]
- `n_pm` u16 [`PM Size : %d`]
- `pitch%` u16 [`Pitch_rate : %d`]
- `(dur%/2 + 10000)/dur%` u16 [`Duration_rate : %d`]
- `vol%` u16 [`Volume_rate : %d`]
- then a blank line.

This is a record-level script of the synthesis (a "pre-selected DTTS"), not a selection trace.

## Open questions

1. **Domain 8 (NUM_SPLIT).** No Paul text produced it, so its `units > 0` acceptance is ported from the decompile but untested.
2. **The heapsort fallback of `us_SortByScore`.** It needs a 32:1 partition imbalance. It is ported from the disassembly but not confirmed to fire in any capture.
3. **Scales.** The physical scale of `featF` (probably Hz, since it is compared with low-byte Hz targets) and the meaning of `featB` (probably energy) are inferred from use, not measured.
4. **Codes above 0x5A.** `0x5B`–`0x5F` appear only in the class-map tables; their origin in the front end is unknown.
