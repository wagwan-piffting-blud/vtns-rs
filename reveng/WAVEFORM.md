# VoiceText Paul waveform generation (vt_eng.dll 3.11.7.1)

Scope: everything between unit selection and the bytes the caller receives:
- unit records and pause records,
- `.dat` decoding (Shorten) and `.upm` pitch marks,
- the join smoother,
- overlap-add (unmodified) and PSOLA (pitch/rate modified),
- output chunking, the emphasis post-filter,
- all output formats,
- the word/phone sync ring and the lip-sync log,
- `waveOut` playback.

All addresses are `vt_eng.dll` VAs (image base `0x10000000`). Function names are the Ghidra renames (`wav_` prefix, 61 functions).

**Evidence tags:**

| Tag | Meaning |
| --- | --- |
| **[D]** | Read from decompile or disassembly |
| **[E]** | Proven by the parity tests against the real engine (see "Verification") |
| **[I]** | Inferred, not proven |

**Port:** `src/wave.rs` (records, decode, smoother, OLA, PSOLA, chunking, sync) plus `src/formats.rs` (emphasis, G.711, Dialogic ADPCM, WAVE/AU/raw writers) plus `src/wave_tables.rs` (generated by a DLL-table extraction script, not part of this repository). Tests are in `tests/wave_parity.rs`.

**Status (2026-09-23): every stage below is bit-exact against the engine on every capture [E].**

## 4. Unit and pause records (`wav_BuildUnitRecords` 0x1002c220)

### 4.1 Algorithm [D][E]

```
records = []
for t in 0..n_targets:
    w = target[t].word
    if (t == 0 and w == first_word) or (t > 0 and target[t-1].word != w):
        pause = wav_PauseBeforeWord(w)                     # -> SS+8 (samples)
        if pause > 0:
            records += silence(len = (dfac(speed%[w]) * pause + 50) / 100,
                               word = first_word, pitch = ch.pitch, dur = 100, vol = ch.volume)
    r = unit(mode = target[t].half, unit = t, word = w, phone = target[t].phone,
             center = W(w).ctx[phone][2], pitch/dur/vol = per-word %)
    wav_FillUnitRecord(r, dbentry[t])
    records += r
    if len(records) > 1099: n = 1100; return        # the sentence-final pause is lost too
if tib.final_pause_ms > 0 and SS.phrase == SS.n_phrases - 1:
    tib.final_pause_ms <<= 4                          # stays shifted in the TIB
    records += silence(len = (dfac(speed%[prev.word]) * final + 50) / 100, word = prev.word, ...)
```

`dfac(r) = ((r >> 1) + 10000) / r`, i.e. round(10000/r). Pause records therefore shrink as speed rises.

### 4.2 `wav_PauseBeforeWord` 0x1002e890 [D][E]

```
p = SS.word_pause_ms[w]                               # -1 unless VTML / the API set one
if p >= 0:
    if w == 0 and tib.cont_flag:
        if SS.word_pause_ms[0] > 0: tib.sync_span = (W0.start, W0.start)
        tib.cont_flag = 0
    return p << 4                                     # ms -> 16 kHz samples
if w == 0:
    if tib.cont_flag: tib.cont_flag = 0; return 0
    return 11000                                      # 687.5 ms, sentence start
switch W(w-1).brk:
    'Z', '^': return 11000
    '[':      return ch.comma_ms << 4                 # 3200 (0xc80) with no channel
    default:  return 0
```

### 4.3 `wav_FillUnitRecord` 0x1002c120: the three `.upm` views [D][E]

| mode | len | ovl_l | ovl_r | upm | n_pm | pos14 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 whole | h1 + h2 − 2·per[1] | 2·per[0] | 2·per[2] | pm_pos | pm1 + pm2 − 1 | pcm_pos |
| 1 first half | h1 | 2·per[0] | 2·per[1] | pm_pos | pm1 | pcm_pos |
| 2 second half | h2 | 2·per[1] | 2·per[2] | pm_pos + pm1 − 1 | pm2 | pcm_pos + (s16)(h1 − 2·per[1]) |

Consequences, verified on all 12,463 captured speech records [E]:
- **A record is its pitch periods, no more, no less:** `len == 2·Σ upm[view]`.
- **Overlap is one period:** `ovl_l`/`ovl_r` are exactly one pitch period, the first and last of the view.
- **`pos14` doesn't reach the audio:** it mixes a byte offset with a sample offset, and nothing in the audio path reads it.

This three-view breakdown was independently peer-reviewed by an outside review, which reached the same conclusions.

## 5. Decoding

### 5.1 `wav_DecodeUnit` 0x1002c8b0 [D][E]

```
read coded_size bytes at db.pcm_pos from .dat[rec.file] into tib+0x118b34
wav_ShortenDecode -> window tib+0x113d14              (the window persists across calls)
start = mode == 2 ? (s16)(db.h1 - rec.ovl_l) : 0      # = first sample of the shared period
dst[0..len) = window[start .. start+len)
if vol != 100: dst[k] = sat16(dst[k] * vol / 100)     # C truncation
```

`sat16(v)`: v ≥ 32767 → 32766 and v ≤ −32768 → −32767. The same saturation is used in the smoother, volume and emphasis paths.

For well-formed units the span ends exactly at the decoded length (§4.3), so the window's stale tail is never read. The Rust `DecodeWindow` still models it.

### 5.2 `.dat` codec: headerless mono Shorten [D][E]

Each unit payload is a raw Shorten v2+ bitstream (Tony Robinson's lossless coder): 1 channel, no `ajkg` header, no QLPC.

**Bit reader:**
- MSB-first, refilled with big-endian 32-bit words.
- `uvar(n)`: count 0-bits up to the first 1 (hi), read n raw bits (lo), return `hi<<n | lo`.
- `svar(n)`: `u = uvar(n+1)`, then `u&1 ? ~(u>>1) : u>>1`.
- `ulong()`: `uvar(uvar(2))`.

**Initial state:** blocksize 256, bitshift 0, nmean 4 (means all 0), history `s[-3..-1] = 0`.

**Command loop** (`cmd = uvar(2)` until QUIT):

| cmd | Name | Action (per sample of a block) |
| --- | --- | --- |
| 0 | DIFF0 | `e = uvar(3)`; `s = svar(e) + coffset` |
| 1 | DIFF1 | `s = svar(e) + s1` |
| 2 | DIFF2 | `s = svar(e) + 2·s1 − s2` |
| 3 | DIFF3 | `s = svar(e) + 3·(s1 − s2) + s3` |
| 8 | ZERO | no energy field; `s = 0` |
| 5 | BLOCKSIZE | `blocksize = ulong()` |
| 6 | BITSHIFT | `bitshift = uvar(2)` |
| 4 | QUIT | end of payload |
| 7 | QLPC | unsupported; the decoder fails |

**Running offset:** `coffset = trunc((2 + Σmeans)/4)`; if `bitshift > 0`, `coffset = (coffset >> (bitshift−1)) >> 1`.

**Block end:**
- `mean = trunc((trunc(bs/2) + Σs)/bs) << bitshift` is pushed into the 4-entry FIFO.
- The history keeps the last 3 samples before the shift.
- Output is `s << bitshift`, clamped only at the top (>0x7fff → 0x7fff) and otherwise truncated to 16 bits.

**Size:** 471 MB of payload for 16 h of audio, about 4.8 bits/sample. It is lossless: the whole bank decodes bit-identically to the engine (verified against a full bank export, all 580,474 units) [E].

## 6. `wav_GeneratePhrase` 0x1002bd90

### 6.1 Record loop and chunking [D][E]

```
if SS.next_record == 0 and tib.chunk_full_flag == 0:     # first entry for this phrase
    wav_BuildUnitRecords(...); if SS.next_record == 0: SS.tail_n = 0
    wav_BuildSyncEntries(...)
for i = SS.next_record .. n-1:
    before = tib.chunk_bytes
    if rec[i].type == SILENCE:
        if chunk_bytes + 2·len > 60000:                   # split exactly at 60000
            zero-fill to 60000; rec[i].len -= filled/2; credit filled/2 to sync; chunk full; return
        zero-fill 2·len bytes; SS.tail_n = 0
    else:
        if tib.smoothed == NULL: tib.smoothed = wav_SmoothJoins(i)       # cached across returns
        est = ((dfac(dur) * rec.len + 50) / 100) * 2                     # rec.len after smoothing
        if chunk_bytes + 2000 + est > 60000: chunk full; return          # resume at the same record
        if !smoothed: wav_DecodeUnit(tib+0x10eef4, rec)
        if pitch == 100 and dfac(dur) == 100: n_epochs = 0
        else: if !smoothed: wav_ReadPitchMarks(tib+0x10ec9c); n_epochs = wav_BuildEpochTable(...)
        wav_PsolaUnit(i); tib.smoothed = NULL
    sync[rec.entry].samples += (chunk_bytes - before)/2; sync[rec.entry].phone[rec.slot] += same
    SS.next_record++
if n == 0: done
tib.chunk_full_flag = 0                                   # phrase finished
```

**Chunking never changes the audio:** the OLA tail, PSOLA state, smoother cache and emphasis state all carry over. It only shows in the DADPCM formats (§8.4) and in the buffer-API call granularity.

**Chunk boundaries are reproduced exactly** by `wave::chunk_ends` on all 92 sweep captures (459 chunks) [E].

### 6.2 Join smoother `wav_SmoothJoins` 0x1002d230 [D][E]

This runs for every speech record, before decoding. It blends the unit's first few periods with the natural recorded continuation of the previous selected unit, and its last few with the natural predecessor of the next one.

#### 6.2.1 Edge decisions (`L`/`R`: 0 off, 1 or 2 weight)

Notation: `lbl(u)` = the global 7-byte label `[L2,L1,C,R1,R2,posbits,flags]` (`ch+0x64 + 7u`); `cur`, `prev`, `next` = the selected uids of targets t, t−1, t+1; `half` = the half-type of target t.

```
L = 2
if t == 0: L = 0
elif lbl(cur).posbits & 0x80 and (lbl(cur).posbits & 0x38) >= 0x18: L = 0
elif half == 2 and prev == cur: L = 0
elif prev == n_units - 1: L = 0
elif half != 2:
    if prev + 1 == cur and lbl(prev).flags & 0x80: L = 0      # NB: prev's flag (1002d395)
    elif not lbl(prev).flags & 0x80: L = 0
    elif not lbl(cur - 1).flags & 0x80: L = 1

R = 2
if t == n_targets - 1: R = 0
elif lbl(cur).posbits & 0x40 and (lbl(cur).posbits & 7) >= 3: R = 0
elif half == 1 and next == cur: R = 0
elif next == 0: R = 0
elif half != 1:
    if cur + 1 == next and lbl(cur).flags & 0x80: R = 0
    elif not lbl(next - 1).flags & 0x80: R = 0
    elif not lbl(cur).flags & 0x80: R = 1
if L == 0 and R == 0: return NULL
```

The first version of the port tested `lbl(cur)` in the `prev + 1 == cur` branch. That error gave ±1..3 errors across whole units in 34 of 42 captures (see the experiment log).

#### 6.2.2 Sources

- **Current unit:** decoded with a copy of the record (so `mode`/`vol` apply); its periods P_c come from its view.
- **Left source** (if L): unit `half == 2 ? prev : prev + 1`, loaded by `wav_LoadNeighbourUnit` with the current record's mode and volume. Its periods are P_l, `nL = n_pm`, and `bL = min(nL, npm, 5)`.
- **Right source** (if R): unit `half == 1 ? next : next − 1`, with P_r, `nR`, and `bR = min(nR, npm, 5)`.

#### 6.2.3 Weights (16-bit) and new periods

```
cL = L ? bL·L : 1        sR = R ? bR·R : 1        W = (s16)(sR·cL)
for k in 0..=npm:  WL[k] = k < bL ? (bL−k)·sR : 0
                   WR[npm−k] = k < bR ? (bR−k)·cL : 0
                   WC[k] = W − WR[k] − WL[k]
for k in 0..npm:
    if WL[k] == 0 and WR[k+1] == 0: P'[k] = P_c[k]
    else:
        acc = (WC[k+1] + WC[k])·P_c[k]
        if WL[k] > 0:   acc += (WL[k] + WL[k+1])·P_l[k]
        if WR[k+1] > 0: acc += (WR[k] + WR[k+1])·P_r[nR − npm + k]
        P'[k] = (acc + W) / (2W)
```

#### 6.2.4 Synthesis

The output goes to `tib+0x10eef4`, zeroed to 10000 samples. Position counters `c`, `l`, `o` start at 0; `r` starts at `Σ P_r[0 .. nR−bR)`.

```
for k in 0..npm:
    if WL[k] == 0 and WR[k+1] == 0: copy P'[k] samples of cur[c..]; c += P_c[k]; o += P'[k]; continue
    out[o..o+P'[k]) += sat16(fadeout(cur+c, P_c[k], P'[k]) · WC[k] / W)
    if WL[k]   > 0: += sat16(fadeout(left+l,  P_l[k],       P'[k]) · WL[k]   / W)
    if WR[k]   > 0: += sat16(fadeout(right+r, P_r[nR−npm+k], P'[k]) · WR[k]   / W)
    out += sat16(fadein(cur+c, P_c[k], P'[k]) · WC[k+1] / W)
    if WL[k+1] > 0: += sat16(fadein(left+l,  P_l[k],       P'[k]) · WL[k+1] / W)
    if WR[k+1] > 0: += sat16(fadein(right+r, P_r[nR−npm+k], P'[k]) · WR[k+1] / W)
    if WL[k] > 0: l += P_l[k];   if WR[k+1] > 0: r += P_r[nR−npm+k]
    c += P_c[k]; o += P'[k]
rec.len = o; rec.n_pm = npm; rec.ovl_l = P'[0]; rec.ovl_r = P'[npm−1]
```

The `+=` accumulations are 16-bit wrapping adds.

The two period windows:

| Function | Window | Placement |
| --- | --- | --- |
| `fadeout(src, p_old, p_new)` (`wav_FadeOutPeriod`) | falling half-Hann over the first `min(p_old, p_new)` samples (`idx = k·4096/len + 4096`) | zero-padded to `p_new` |
| `fadein(src, p_old, p_new)` (`wav_FadeInPeriod`) | rising half over the last `min(p_old, p_new)` samples of the period | right-aligned in `p_new` |

Every window product is §7.0's `wmul`.

## 7. Overlap-add

### 7.0 Window product `wmul(w, s)` [D][E]

The window is `float hann[8192]` at 0x1006d1b0 (length word 0x1006d1ac). It is Hann to within 2e-7, so treat it as data and not as a formula.

Each windowing loop computes:

```
FLD dword [0x1006d1b0 + 4·idx]; FILD s; FSTP qword; FMUL qword; FSTP qword   ; exact in f64
v >= 32767.0 -> 32766 ; v <= -32768.0 -> -32767 ; else __ftol(v) (truncation, 0x1006479c)
```

The bounds are the f64 constants at 0x100751b8 / 0x100751b0. The result is stored as s16.
- Rising half: `idx = k·4096/L`.
- Falling half: `idx = k·4096/L + 4096`.

### 7.1 `wav_OlaUnitUnmodified` 0x1002aac0 (pitch = dur = 100) [D][E]

```
L = ovl_l; tn = SS.tail_n (tail = tib+0x10cd58)
if not (tn > L and L < 1):
    A = zeros(L)
    if 0 < tn <= L: A[k] = wmul(fall(k, tn), tail[k])  k < tn
    if tn > L:      A[k] = wmul(fall(k, L),  tail[k])  k < L
    out[k] = wmul(rise(k, L), src[k]) + A[k]  (16-bit)  k < L
mid = max(0, len − ovl_r − L); out += src[L .. L+mid)
SS.tail_n = len − mid − L                             # normally = ovl_r
if i < n−1 and rec[i+1].type != SILENCE: tail = src[len−tail_n .. len)     # carried
else: out += wmul(fall(k, tail_n), src[len−tail_n+k]); SS.tail_n = 0     # flushed
```

So each unit is cross-faded into its predecessor over its own first pitch period, and its last period is held back as the next unit's fade-out material.

### 7.2 Epochs [D][E]

`wav_BuildEpochTable`: for `k < n_pm − 1`, the epoch is `{pos = Σ P[0..k), P_left = P[k], P_right = P[k+1], dfac(dur), pitch}`. When `n_pm == 1` there is a single `{0, ovl_l − 1, 1, dfac, pitch}`.

`wav_FindNearestEpoch(t)`:
- If `t >= last.pos + last.P_left + last.P_right`, fail.
- Otherwise return the first k minimizing `|pos + P_left − t|` (strict `<`, starting from 20000).

### 7.3 `wav_PsolaUnit` 0x1002afb0 (pitch or dur ≠ 100) [D][E]

```
if pitch == 100 and dur == 100: return wav_OlaUnitUnmodified
op = 0; lim = epoch[0].P_left; prev_pr = 0
e = nearest(lim·100 / dfac)
while e:
    L = e.P_left·100 / e.pitch;  L = max(L, P_left/16); L = min(L, 31·P_left/16)   # signed /16
    if L − P_left + op > lim: L = P_left − op + lim
    A: op != 0        -> fade out the copied right period:   den = L >= prev_pr ? prev_pr : L
       op == 0, tail  -> fade out the carried tail:           den = L >= tn ? tn : L
       else zeros
    B: L >= P_left -> B[L−P_left+k] = wmul(rise(k, P_left), src[pos+k])  k < P_left (zeros before)
       else        -> B[k]          = wmul(rise(k, L), src[pos − L + P_left + k])  k < L
    dst[op+k] = A[k] + B[k] (16-bit)  k < L
    op += L; copy src[pos+P_left .. +P_right) to dst[op..]; prev_pr = P_right
    lim = op + P_right; e = nearest(lim·100 / e.dfac)
if op == 0: return                                     # nothing committed, tail untouched
SS.tail_n = prev_pr
if i < n−1 and next is not silence: tail = dst[op .. op+prev_pr); commit op samples
else: dst[op+k] = wmul(fall(k, prev_pr), dst[op+k]); commit lim samples      # tail_n not cleared
```

This is a TD-PSOLA variant:
- **Pitch:** each output period is the analysis period scaled by 100/pitch%, clamped to [P/16, 31P/16].
- **Rate:** the analysis cursor advances by the duration factor, so periods repeat or drop.
- **Windowing:** one Hann cross-fade per period, over the new period length; the right-hand period is copied verbatim.

Changing pitch alone changes the total length (e.g. prose at 50–200%: 48,888 → 44,002 samples).

## 8. Output

### 8.1 Emphasis (`wav_NextChunkWithEmphasis`) [D][E]

`k = ch+0x4cfc`, clamped to ±95; `k = 0` skips the filter. The state is `tib+0x1210d4` (starts at 0) and carries across chunks.
- **k > 0 (IIR, low shelf):** `y[i] = sat16(x[i] + (y[i−1]·k + 50)/100)`, evaluated forward. The state is the last output.
- **k < 0 (FIR, pre-emphasis):** `y[i] = sat16(x[i] + (x[i−1]·k + 50)/100)`, evaluated backward in place. The state is the last input.

The division is C truncation (`0x51eb851f` magic, `>>5`, sign fix).

### 8.2 G.711 [D][E]

The lookup tables are built at load for every s16 value:

| Table | Location | Encoder |
| --- | --- | --- |
| µ-law | `common+0x841c` | `wav_Linear2Ulaw` 0x1002e720 |
| A-law | `common+0x1841c` | `wav_Linear2Alaw` 0x1002e780 |

**A-law** is Sun g711.c `linear2alaw` on `s>>3`:
- Segment table `{31,63,127,255,511,1023,2047,4095}` at 0x1007e0f8.
- Mask 0xd5 (positive) / 0x55 (negative, `pcm = −1 − pcm`).
- Segment ≥ 8 gives `0x7f ^ mask`.

**µ-law** is the classic `exp_lut` encoder:
- Sign 0x80 with negation done in int.
- Clip compared as s16 at 0x7f7b, bias 0x84.
- `exp = exp_lut[(v>>7)&0xff]` (256 ints at 0x1007dcf8), `mant = ((s16)v >> (exp+3)) & 15`, result `~(sign|exp<<4|mant)`.

The engine's int/s16 mixing makes −32768 encode to 0x7f (a standard encoder gives 0x00). This is reproduced.

### 8.3 U8 (tag 0x99) [D][E]

`byte = (s8)(s/256) + 0x80`, with truncating division.

### 8.4 Dialogic/OKI ADPCM, "DADPCM" (fmt 3, buffer fmt 3) [D][E]

- **Input:** 12-bit samples, `s>>4`.
- **Steps:** 49 values at 0x1007dc30 (16..1552).
- **State:** `{pred, index}` at `tib+0xeddf4`.

**Encode** (`wav_DadpcmEncodeSample`):
```
d = s − pred (s16); sign 8 if d < 0 (d = −d)
code |= 4 if d >= step (d −= step); |= 2 if d >= step/2 (d −= step/2); |= 1 if d >= step/4
```

**Update** (`wav_DadpcmUpdate`):
```
Δ = step/8 [+ step/4 if 1] [+ step/2 if 2] [+ step if 4]; negate if 8
pred = clamp((s16)(pred + Δ), −2048, 2048)
index = clamp(index + adj, 0, 48), where adj = −1 for codes 0..3 and 2/4/6/8 for 4..7 (`wav_DadpcmIndexAdjust`)
```

**Packing** (`wav_DadpcmEncodeChunk`), per engine chunk of n samples:
- It writes n/2 bytes, high nibble first.
- The last sample of an odd-length chunk is dropped and never encoded.
- The state resets only before the first chunk of the request.

The file writer and the buffer API (15000 bytes per call, overflow carried) produce the same stream. This is the one format where the engine's 60000-byte chunking is visible, which is why `wave::chunk_ends` exists.

### 8.5 WAVE (`wav_TextToWaveFile` 0x1001e930) [D][E]

The header is kept in the TIB and rewritten at fixed offsets after every chunk. Data is appended with `SEEK_END`. Fields are little-endian.

| tag | fmt size | wFormatTag | bits | block | extra | header bytes |
| --- | --- | --- | --- | --- | --- | --- |
| 1 (fmt 4) | 16 | 1 | 16 | 2 | — | 44 |
| 0x99 (fmt 5) | 16 | 1 | 8 | 1 | — | 44 |
| 6 (fmt 7) | 18 | 6 (A-law) | 8 | 1 | cbSize 0 + `fact`(4) = samples | 58 |
| 7 (fmt 8) | 18 | 7 (µ-law) | 8 | 1 | same | 58 |

- **RIFF size:** `data + 0x14 + fmt_size` (+12 for `fact`).
- **Rate:** 16000, mono; avg bytes/s = 16000·block.
- **Tag 0x11 (IMA ADPCM, `FUN_1001c8b0`)** is coded, but no public fmt reaches it: fmt 6 falls into `VT_TextToFile_ENG`'s default case and returns an error.

### 8.6 Raw and AU; the file-position cache [D][E]

The raw formats (fmt 0/1/2/3) write data at an explicit running offset with no header.

`wav_FileWriteAt(h, pos, whence, ...)`:
- It seeks only when `whence != 0` or `pos != h+0xc`.
- Writes advance `h+0xc`.

**fmt 9 (`.au`) is broken by this.** `wav_TextToAuFile` writes the seven header fields of `wav_InitAuHeader` (".snd", 28, size, 1, 16000, 1, 0) all at "pos 0". Each write after the first seeks back to 0 and overwrites the previous field. The file ends up as **4 zero bytes (the annotation field) followed by raw µ-law** data, not a valid AU file.

The port reproduces this byte for byte. `formats::au_header` builds the header the engine intended, for anyone who wants a valid file.

## 9. Word/phone sync

### 9.1 Ring (`wav_BuildSyncEntries` 0x1002c530) [D][E]

The ring has 600 entries of 0x24 bytes at `*(tib+0x47774)`. The head is at `ring+0xc` and wraps at 600.

**Entry fields:**

| Off | Type | Field |
| --- | --- | --- |
| +0 | s16 | n phone slots |
| +4 | ptr | phone slots, `{s32 samples, u16 code}` |
| +8 | s32 | samples |
| +0xc / +0x10 | s32 | char span (inclusive) |
| +0x14 / +0x18 | s32 | sentence first/last char |
| +0x1c | s32 | n words |
| +0x20 | s32 | word index |

**Entry creation, per phrase record k:**
- A new entry starts at k = 0, or whenever the word or the type differs from record k−1.
- A unit entry takes `W(word).start/end` and updates the last span (`tib+0x4777c/80`).
- A silence entry copies the last span, so a pause shows as the preceding word's text.
- `wav_PauseBeforeWord` can reset the span (§4.2).

**Phone slots:**
- A new slot starts when the word, phone or type changes.
- The slot's code is `LIPSYNC_CODE[rec.center]`, a 256-byte table at 0x1007daa8: phone code → base-phone index 0..38 with stress folded, and 40 for silence (0x5a).

`wav_GeneratePhrase` adds each record's output samples to its entry and phone slot (§6.1). Word boundaries for `VT_TextToBufferEX_ENG`'s SYNCINFO and for SAPI word events come from here.

### 9.2 Lip-sync log (`VT_TextToLipSyncLog_ENG(text, path, spk, pitch, speed, vol, pause, dict, type)` → `wav_TextToLipSyncLog`) [D][E]

The log is opened in text mode, so the CRT writes CRLF. After each chunk, `wav_FlushLipSyncLog` prints every ring entry created before the previous flush.

**Per entry:**
- `"%2d (%3s) : %d \n"` for each phone slot: code, name (5-byte entries at 0x1007bbd4), samples. Silence prints as `"%2d (sil) : %d \n"`.
- `"-------------------------------\n"`
- `"%d - %d %s : %d \n"`: start, end, `text[start..=end]`, samples.
- `"===============================\n\n"`

**On close:** `"Total  Word Length : %d\n"` and `"Total Phone Length : %d\n"`.

`wave::lipsync_log` reproduces the file byte for byte.

## 10. Playback (`VT_PLAYTTS_ENG` → `wav_PlayStart` 0x10026b40) [D]

**Setup:**
1. Prime the first sentence.
2. Render chunk 1.
3. `waveOutOpen(&hwo, device = DAT_1007d6e0 (VT_SetSoundCardID_ENG), {PCM, 1 ch, 16000, 32000, 2, 16}, hidden window DAT_100a8418, CALLBACK_WINDOW)`.
4. Post the caller's `umsg` with the first word's span.
5. Render chunk 2.
6. `FUN_10026d00` prepares and writes both buffers.

**Streaming:** `WOM_DONE` on the hidden window refills the buffers, which gives double-buffered streaming. Pause, restart and stop map onto `waveOutPause` / `waveOutRestart` / `waveOutReset` (`VT_PAUSETTS_ENG` etc.).

This path is not ported; the native engine hands PCM to its caller.

## 13. Open items

- **`wav_PlayStart` / `waveOut` callback details** (`FUN_10026d00`, the hidden window procedure, the `umsg` word-event payloads): documented only at the call level and not ported.
- **Buffer-API SYNCINFO** (`VT_AllocSyncInfo_New_ENG` … `VT_TextToBufferEX_ENG`): the ring is ported, but the exported struct layout that copies it out is not decoded.
- **IMA ADPCM writer `FUN_1001c8b0`** (tag 0x11): unreachable through the public fmt codes and not ported.
- **Stage limits** (`tib+0x20` = 1/2/3) and the `.dtt` logging path (`tib+0x122851`, `VTDTTS_MakeInfo_ENG`): the waveform side just skips synthesis. The dump format belongs to unit selection.
- **Undefined behaviour:** units whose smoothed period count exceeds 300 would overflow the weight arrays, and a record chunk-check on an empty chunk with `est > 58000` would loop forever. Neither occurs in the 92 captures.
